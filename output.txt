### Architecture Overview
- **Data Ingestion and Indexing**: Data is transformed into an indexed format suitable for efficient similarity search.
- **Context Retrieval**: Uses dense embedding models to convert raw text into vectors, along with metadata for context reuse.
- **Augmented Generation**: Generates a coherent response based on the original user query.

### Key Components
1. **Database (Indexing)**:
   - A database stores structured data and is optimized for nearest neighbor search.
2. **Context Retrieval**:
   - The system identifies relevant chunks from the retrieved text segments using embedding models like Milvus or Qdrant.
3. **Augmented Generation**:
   - An augmented prompt contains the original user query, a chunked version of the user query, and instructions to ground answers within the context.

### Detailed Technical Challenges
- **Retrieval Precision vs. Recall**: Balancing retrieval precision with recall issues when retrieving too many irrelevant chunks.
- **Context Window Saturation**: Preventing "Lost in the Middle" phenomenon where retrieval results are less relevant to the user's request.
- **Chunking Strategy Trade-offs**: Fixed-length chunking often breaks context boundaries, requiring more semantic or recursive chunking strategies.

### Evaluation Frameworks
Modern RAG evaluation relies on automated frameworks (e.g., Ragas) measuring three foundational metrics:

1. **Context Relevance**:
   - Measuring whether the retrieved chunks are pertinent to the query.
2. **Groundedness (Faithfulness)**:
   - Assessing if generated answers rely strictly on the retrieved context without introducing ungrounded assertions.
3. **Answer Relevance**:
   - Evaluating how directly and accurately the final response addresses the original user prompt.

### RAG Components
- **Modular RAG**: Modular components include query rewriting, routing mechanisms, query expansion, and iterative multi-hop retrieval pipelines.
- **Self-RAG (Self-Reflective RAG)**: The model autonomously evaluates context relevance during retrieval to make decisions about whether to retrieve the document or continue processing.

### Advanced RAG Patterns and Techniques
1. **Retrieval-Augmented Generation (RAG)**:
   - Integrates external knowledge sources into text generation.
2. **Context Retrieval**:
   - Extracts relevant information from a database using dense embedding models, enabling dynamic retrieval of context.
3. **Augmented Generation**:
   - Generates coherent responses by combining raw data with contextual knowledge.

### Architectural Comparison
- **Standard LLM vs RAG vs Fine-Tuning**: The standard llm is static parametric and trained on limited training data while RAG adapts to complex queries and low-quality retrievals.
- **Knowledge Source (Static Parametric Weights)**:
  - Static weights are not used, as the model's parameters are fixed during training.

### Advanced RAG Patterns
1. **Modular RAG**: Uses specialized modules for query rewriting, routing mechanisms, query expansion, etc., allowing more flexibility.
2. **Self-RAG (Self-Reflective RAG)**: Evaluates context relevance automatically to improve decision-making.

### Future Directions
- **Fine-tuning**: More advanced techniques like RAG that combine various components for better performance and reliability.
